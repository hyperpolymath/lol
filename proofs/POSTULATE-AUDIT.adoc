== Current state (2026-10-04)

The corpus was rebuilt around a quarantined trust base. All postulates now
live in exactly one module — `InformationTheory/Axioms.agda`, compiled without
`--safe` because Agda's `--safe` rejects `postulate` (Agda test
`SafeFlagPostulate`) — and every one of them is tagged, named, classified,
and budget-enforced against `{manifest}` by `scripts/audit-trust-base.py` in
CI (`.github/workflows/echidna-verify.yml`, issue #4).

The audit now contains **6 postulates**:

- **4 legitimate IEEE-754 `ffi-fact` axioms** (true facts about
  correctly-rounded float ops that Agda cannot derive from opaque primitives)
- **2 `conjecture` axioms** (Gibbs' inequality and Lin's JSD bound lifted to
  floats — honest open debt, never used by the proven theorems)
- **0 uninterpreted where-clause relations** — the 2026-04 correctness bug is
  structurally impossible now (see below)

[cols="3,2,3,2",options="header"]
|===
| Axiom | Class | Statement (roughly) | Why axiom

| `log₂-nonpos` | ffi-fact | 0 ≤ v ≤ 1 → log₂ v ≤ 0 (IEEE, incl. v = 0 → −∞)
| Float `log` is a runtime primitive; no real-analysis model in scope
| `mul-sign` | ffi-fact | a ≥ 0 ∧ b ≤ 0 → −(a·b) ≥ 0 (correctly-rounded ×)
| Sign/rounding law of IEEE multiplication
| `add-nonneg` | ffi-fact | a ≥ 0 ∧ b ≥ 0 → a + b ≥ 0
| Same, for addition (no associativity is ever claimed)
| `add-comm` | ffi-fact | a + b ≡ b + a (bitwise)
| IEEE addition is commutative even under rounding; NaN payload propagation
  is symmetric
| `kl-nonneg` | conjecture | Σ p·log₂(p/q) ≥ 0 for [0,1] entries summing to 1
| Gibbs over reals; float rounding bridge is real proof work (Phase 2 open)
| `js-bounded` | conjecture | 0 ≤ JSD ≤ 1 (bits)
| Lin (1991); same rounding bridge plus log-sum inequality
|===

**Discharged since the 2026-04 audit** (were postulates, now theorems proven
in `InformationTheory` using only the four `ffi-fact` axioms):

* `entropy-nonneg` — per-entry guard `plogpB` + `sumF` induction +
  `lookup-map` transport.
* `js-symmetric` — `zipWith-comm` on the midpoint construction +
  `add-comm`; the swap never needs associativity.
* The five float-arithmetic postulates from the 2024 baseline
  (`log₂`, `_*f_`, `_+f_`, `negateF`, `_/f_`) are gone entirely: those ops are
  *defined* by re-exporting `Agda.Builtin.Float` primitives through
  `Data.Float`, which is not postulation and was correctly never in the trust
  base after the rebuild.

== Historical: 2026-04-05 audit (pre-remediation state)

`information_theory.agda` (the pre-split file) contained **9 postulates**.
Verdicts, preserved for provenance:

* 4-5 were "legitimate FFI axioms" for float ops bridged to runtime — later
  recognised as definable via `Agda.Builtin.Float` re-exports.
* 4 (`entropy-nonnegative`, `kl-nonnegative`, `js-symmetric`, `js-bounded`)
  were theorems postulated rather than proven.
* 1 was a relation *declaration* smuggled into a `where` clause.

=== The correctness bug (now regression-gated)

The old corpus declared `_≥_` and `_≤_` as **per-postulate `where`-clause
relations** (`where _≥_ : Float → Float → Set`). Uninterpreted relations are
satisfied vacuously by every pair of floats, so `entropy d ≥ 0.0` quantified
over an empty proposition: *trivially provable, meaningfully false*. Two
layers of gate now prevent this class:

1. Agda itself: `where` clauses on `postulate` signatures don't parse, and
   even when abused via module-level declarations, the statements over
   unconstrained `Probability` records are **refutable** (e.g. `p = 2.0`
   gives `−p·log₂ p < 0`, and unnormalised pairs break Gibbs). The rebuild
   replaces the records with a `Distribution` carrying `lower`, `upper` and
   `normalised` hypotheses expressed through the *computational* order
   `_≤ᶠ_ := T (… ≤ᵇ …)`, so each claim evaluates against the real IEEE
   comparison.
2. `scripts/audit-trust-base.py` fails on any `where _≥_/_≤_ :` shape inside
   the trust base, and on any untagged or off-manifest postulate.

== Remediation ledger

*Phase 1 — fix the order relation bug*: **DONE 2026-10-04.** Computational
`_≤ᶠ_`/`_<ᶠ_`/`_≥ᶠ_` module-wide in `Foundations`; where-clause relations
eliminated and regression-gated.

*Phase 2 — prove the 4 theorems*: **PARTIAL 2026-10-04.** `js-symmetric` and
`entropy-nonneg` are proven. `kl-nonneg` and `js-bounded` remain tagged
`conjecture` axioms — each requires real-analysis lemmas (log-sum/Jensen)
over a reals model plus a rounding bridge; `Probability`-style range +
normalisation hypotheses now make their statements *true-as-stated modulo
rounding* rather than vacuous.

*Phase 3 — convert FFI postulates to trust-tagged axioms*: **DONE.** The
audit asked for `@trust(level=axiom, prover=ffi, since=...)` annotations;
Agda has no annotation syntax, so the mechanism is the `ECHIDNA:trust
<class> :: <name>` line tag consumed by the audit script and enforced by
manifest equality (`{manifest}`), which is strictly stronger than comments:
the tag set and the source are checked for exact bi-directional match.

*Phase 4 (new, from issue #4) — CI that type-checks this tree*: **DONE.**
Workflow ported from the stranded `standards` job with its two structural
notes applied (no workflow-level `paths:` filter on `pull_request`;
fail-closed corpus assertion), and with the type-check made a hard failure
rather than the advisory `::warning::` the standards copy used.

== Recorded as VeriSimDB octads (once deployed)

Each postulate produces a `proof-status` octad with:

- `trust_level`: `axiom` for `ffi-fact`, `postulate` for `conjecture`
- `axioms_used`: the four `ffi-fact` names for any proven theorem
- Temporal: `verified_at` = null while `verified` = true for proven theorems
  (`entropy-nonneg`, `js-symmetric`); `conjecture` entries remain
  `verified_at: null` by design.
